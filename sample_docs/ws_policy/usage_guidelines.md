# KnowledgeQA 使用规范

本文档适用于部署 KnowledgeQA 的团队及终端用户，说明数据安全、演示限制与合规使用建议。

## 资料库使用原则

1. **主题隔离**：技术文档、产品说明、内部制度应分库管理，避免在同一库混入无关材料导致检索噪声。
2. **上传前审查**：确认文档不含未经授权的个人隐私、密钥、客户机密。
3. **来源可信**：优先上传经审核的正式版本，过期文档应及时删除或替换。

## 数据与隐私

### 本地存储

- 上传文件保存在服务器 `data/uploads/`
- 向量索引保存在 `data/chroma/`
- 资料库元数据保存在 `data/workspaces.json`

### API Key 安全

- **禁止**将生产环境 API Key 写入前端代码或提交到 Git
- 用户 Key 应仅保存在本人浏览器；公用电脑使用后请清除站点数据
- 服务端 `.env` 中的 `DEMO_API_KEY` 应有额度监控，并定期轮换

### 敏感信息

- 不要将含密码、Token、私钥的文档上传至演示环境
- 对外演示建议使用 `sample_docs/` 中的示例资料，而非真实业务数据

## 演示模式运营规范

当站点开启演示模式时，建议遵守以下限制（默认值可在 `.env` 调整）：

| 限制项 | 默认值 | 说明 |
|--------|--------|------|
| 每日提问次数 | 10 次/IP | 防止滥用 |
| 每分钟次数 | 2 次 | 防止刷接口 |
| 单次字数 | 500 字 | 控制 Token 成本 |
| 聊天历史 | 不保存 | 演示会话不落库 |

运营人员应：

- 在界面显著位置标注「演示模式」
- 监控 `data/demo_quotas.json` 与 API 账单
- 引导重度用户配置自有 Key 进入完整模式

## 内容合规

- 不得利用本系统生成违法、侵权、欺诈内容
- 大模型回答基于已上传资料，**资料错误会导致回答错误**，重要决策需人工复核
- 引用来源功能用于核对原文，不能替代法务或合规审批

## 备份与恢复

- 定期备份整个 `data/` 目录
- 更换嵌入模型（`EMBEDDING_MODEL`）后系统会自动重建向量；备份时建议同时保留 `embedding_meta.json`
- 灾难恢复：还原 `data/` 后重启服务即可，无需重新上传（若 uploads 完整）

## 违规处理（内部部署参考）

| 级别 | 行为示例 | 建议措施 |
|------|----------|----------|
| 轻微 | 上传无关个人文件 | 提醒并删除文档 |
| 中等 | 在演示环境上传机密材料 | 立即删除、通报管理员、轮换 Key |
| 严重 | 故意刷接口、导出他人数据 | 封禁 IP、停用账号、按公司制度处理 |

## 支持与反馈

- 检索不准：先使用「检索预览」，尝试换关键词或补充文档
- 部署问题：查阅技术文档库中的《部署与运行指南》
- 功能建议：欢迎在项目仓库提交 Issue
